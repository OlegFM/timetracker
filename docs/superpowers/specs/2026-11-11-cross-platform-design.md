# TimeTracker на Linux и macOS — дизайн

Дата: 2026-11-11 · Статус: на согласовании · Основа: [docs/ideas/cross-platform.md](../../ideas/cross-platform.md)

## 1. Зачем

TimeTracker 0.1.0 работает только на Windows, а README обещает «macOS & Linux soon».
Сборки для Linux и macOS нужны **людям, которым автор даёт программу**, а не ему самому:
автор работает на Windows. Человек на Linux или Mac должен скачать файл со страницы
релиза, запустить его и пользоваться программой так же, как на Windows: таймер с паузой,
мини-таймер поверх окон, значок в трее, автозапуск, отчёты, резервные копии.

Проект открытый и делается на энтузиазме, поэтому **никаких платных подписок**
(Apple Developer и т. п.). Платные шаги откладываются и делаются, только если на них
соберутся донаты.

## 2. Цели

- **Linux, релиз 0.2.0.** AppImage и `.deb` для x86_64.
- **macOS, релиз 0.3.0.** Один универсальный `.dmg` (Apple Silicon + Intel).
- Одинаковое поведение на всех системах. Там, где у системы свои привычки или ограничения,
  программа следует системе (раздел 5).
- Windows-сборки выходят в тех же релизах, как раньше (setup.exe, portable.zip).
- CI собирает и тестирует проект на всех трёх системах.
- README и страница релиза объясняют установку на каждой системе, включая обход
  предупреждения macOS о неизвестном разработчике.

## 3. Не цели

- Нотаризация и подпись Apple (USD 99 в год). Записывается в `docs/ideas/` как
  «после донатов».
- Flatpak, Snap, AUR, `.rpm`, Homebrew. Могут появиться позже.
- Linux на ARM (aarch64).
- Встроенная проверка обновлений на Linux и macOS. Там она остаётся выключенной (не
  компилируется), как сейчас на Windows без переменных сборки.
- Родной Wayland-режим (раздел 5.2).
- Замеры памяти и скорости запуска на новых системах. README не обещает для них цифр.

## 4. Анти-цели

- **Регрессия на Windows.** Поведение, установщик, автозапуск, single-instance и
  файлы релиза Windows не меняются. Windows-код в `platform/` не переписывается «заодно».
- **Таймер, который идёт невидимо.** Нельзя оставить программу работающей без окна и без
  значка, до которого пользователь может добраться.
- **Потеря данных при переходе.** Пути к базе и логам — стандартные для системы и не
  меняются между версиями.

## 5. Поведение на каждой системе

### 5.1 Общее для Linux и macOS

- **Автозапуск.** Переключатель в настройках называется «Запускать при входе в систему»
  (на Windows остаётся «Запускать вместе с Windows»). Новая строка переводится на 4 языка.
  - Linux: `~/.config/autostart/TimeTracker.desktop`.
  - macOS: стандартный механизм входа пользователя (LaunchAgent или Login Items — выбор
    строителя).
  - Запуск из автозапуска идёт с `--minimized`, как на Windows.
- **Один экземпляр.** Второй запуск показывает окно первого и завершается, как на
  Windows. Механизм — на выбор строителя (файл-замок, локальный сокет).
- **Ошибка при запуске.** Сообщение в окне (через `rfd`, уже в зависимостях), а не
  только в логе.
- **Значок приложения** в заголовке окна, в меню приложений и в Dock — тот же, что на
  Windows.
- **Данные и логи** — через `directories::BaseDirs`, как сейчас:

  | Система | База данных | Логи |
  |---|---|---|
  | Linux | `~/.local/share/TimeTracker/timetracker.db` | `~/.local/share/TimeTracker/logs` |
  | macOS | `~/Library/Application Support/TimeTracker/timetracker.db` | `~/Library/Application Support/TimeTracker/logs` |

  (Решение автора дизайна: это то, что уже возвращает `BaseDirs`; ничего не переносим.)

### 5.2 Linux

- **Целевая система:** Ubuntu 22.04 и 24.04 с GNOME «как из коробки». Проверяет автор в
  виртуалке Ubuntu.
- **Мини-таймер поверх окон — обязательно** (решение пользователя). Wayland не даёт
  программе держать окно поверх других и задавать его положение, поэтому программа **всегда
  работает через XWayland** (X11), даже в сессии Wayland. Цена, которую пользователь
  принял: на дробном масштабе (125 %, 150 %) окна могут быть слегка размыты.
- **Трей.**
  - В Ubuntu трей есть из коробки (расширение AppIndicator включено по умолчанию). Там
    всё как на Windows: значок с состоянием таймера, меню, «закрыть в трей».
  - Левый клик по значку на Linux открывает меню (отдельного события клика там нет).
    Это нормально.
  - **Если трея нет** (например, «голый» GNOME в Fedora): значок не создаётся, крестик
    закрывает программу, а пункт «закрывать в трей» в настройках недоступен. Таймер при
    этом не теряется: запущенная запись хранится в базе и продолжает идти, как после
    обычного перезапуска. Запуск с `--minimized` без трея показывает окно свёрнутым.
    (Решение автора дизайна: это самый простой вариант, который не нарушает анти-цель
    «невидимый таймер».)
- **AppImage** должен запускаться на свежей Ubuntu 22.04/24.04 без установки чего-либо
  ещё, кроме `chmod +x` (или «Разрешить запуск» в свойствах файла). Если это окажется
  невозможно (например, из-за `libfuse2`), README даёт одну команду установки.
- **`.deb`** ставит программу в меню приложений (файл `.desktop` и значок) и тянет
  нужные библиотеки для трея через зависимости пакета.
- Сборка — на самой старой поддерживаемой Ubuntu (22.04), чтобы бинарник работал и на
  новых.

### 5.3 macOS

- **Без нотаризации** (решение пользователя). Пользователь открывает программу через
  «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».
  README и описание релиза дают пошаговую инструкцию.
- **Ad-hoc подпись** (бесплатная, без сертификата) обязательна: без неё бинарник для
  Apple Silicon не запускается.
- **Универсальный бинарник** (aarch64 + x86_64) в одном `.app` внутри `.dmg`.
  Минимальная версия macOS — на выбор строителя, не ниже той, что поддерживают Slint и
  winit.
- **Строка меню вместо трея.** Значок таймера — в строке меню вверху экрана, с тем же меню.
  Цветной значок состояния остаётся цветным.
- **Закрытие окна.** Настройка «закрывать в трей» работает и на macOS, по умолчанию
  включена. Включена: программа остаётся в строке меню. Выключена: крестик закрывает
  программу, как на Windows. Подпись настройки на macOS говорит о строке меню, а не о трее
  (новая строка на 4 языка). Выход — `Cmd+Q` или «Выйти» в меню значка.
  (Решение автора дизайна: одно поведение на всех системах.)
- **Значок в Dock** виден, только пока открыто главное окно. Мини-таймер его не
  показывает и не попадает в `Cmd+Tab`, как на Windows он не попадает на панель задач.
  (Решение автора дизайна.)
- **Проверяет** знакомый автору разработчик с Mac. У автора Mac нет: macOS-сборка
  делается только в CI, и правки идут циклами «сборка → отзыв тестировщика».
  Промежуточные сборки тестировщик получает из предрелизов (раздел 6).

## 6. Релизы

| Версия | Что добавляется | Кто проверяет |
|---|---|---|
| 0.2.0 | Linux: AppImage, `.deb` (+ Windows, как раньше) | автор, Ubuntu в виртуалке |
| 0.3.0 | macOS: `.dmg` (+ Windows и Linux) | разработчик с Mac |

(Нумерация — решение автора дизайна.) Каждый релиз — отдельный план, отдельная ветка,
свой раздел в CHANGELOG и QA-чеклисте. Общая часть (абстракция платформы, CI-матрица)
входит в 0.2.0.

**Промежуточные сборки — предрелизы** (решение пользователя). Перед релизом автор ставит
тег вида `v0.3.0-rc.1`, `v0.3.0-rc.2`… CI собирает файлы для всех систем и сам публикует
на GitHub страницу с пометкой **Pre-release**. Тестировщик скачивает файлы по ссылке, без
аккаунта GitHub. Предрелиз не становится «Latest», и README на него не ссылается.
- Механизм появляется в 0.2.0, вместе с CI-матрицей: автор может так же проверять
  Linux-сборки. (Решение автора дизайна: одна общая часть, а не отдельная для macOS.)
- Обычные релизы (`v0.2.0`, без `-rc`) публикуются, как сейчас. Публикует ли их CI сам
  или автор вручную — на выбор строителя.
- Старые предрелизы можно удалять после выхода релиза; это не обязательно.

## 7. Ограничения

- Rust 1.95, Slint 1.18.1 (только software renderer), `tray-icon`, `auto-launch`,
  `directories` — как сейчас. Новые зависимости — только если без них никак, с проверкой
  `cargo deny`.
- Платформенный код остаётся в `crates/tt-app/src/platform/`. Вне этой папки нет
  `cfg(target_os)`, кроме неизбежного (например, `main.rs`).
- `cargo fmt`, `clippy -D warnings`, `cargo test --workspace` и `cargo deny` проходят на
  всех трёх системах в CI.
- Не копировать код и строки solidtime (AGPL-лицензия проекта своя).
- Сетевые установки в CI допустимы (это сборочная среда), локально — нет.

## 8. Что оставлено строителю

- Как устроен слой платформы: `cfg`-модули, трейт или отдельные файлы на систему.
- Как включить XWayland: переменные окружения при старте, опция winit/Slint.
- Как запустить GTK для `tray-icon` на Linux рядом с событийным циклом winit.
- Как определить, что трея нет.
- Механизм single-instance и автозапуска на macOS.
- Инструменты упаковки: `appimagetool`/`linuxdeploy`, `cargo-deb` или ручной `dpkg-deb`,
  `create-dmg` или `hdiutil`.
- Как генерировать PNG и `.icns` из существующего значка.

## 9. Что надо проверить руками (QA)

Вписывается в `docs/qa-checklist.md`, по разделу на систему. Минимум:

- Установка из каждого файла; программа есть в меню приложений (Linux) / в «Программах»
  (macOS).
- Таймер: старт, пауза, продолжение, стоп; запись через полночь режется.
- Мини-таймер поверх окон, перетаскивается, помнит положение после перезапуска.
- Трей / строка меню: состояние значка, все пункты меню, «закрыть в трей».
- Linux без трея: крестик закрывает, таймер после перезапуска продолжается.
- Автозапуск включается и выключается; после входа в систему программа в трее.
- Второй запуск показывает окно первого.
- Резервная копия и восстановление; экспорт CSV/XLSX открывается.
- Четыре языка, включая китайский (шрифт виден).
- Windows: короткий прогон старого чеклиста — ничего не сломалось.
