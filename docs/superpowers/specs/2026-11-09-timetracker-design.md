# TimeTracker — дизайн standalone-приложения учёта времени

Дата: 2026-11-09 · Статус: на согласовании

## 1. Зачем

Нужен **личный локальный трекер времени для Windows** с функциональностью
[solidtime](https://github.com/solidtime-io/solidtime) (веб-приложение
Laravel + Vue), но без серверной части и всего, что связано с аккаунтами.
Это инструмент, чтобы понимать, **сколько времени ушло на задачи** — не
инструмент контроля распорядка дня. Приложение работает весь день в фоне,
поэтому **не должно отнимать оперативную память** — отсюда нативный GUI без
веб-движка. Внешне — современный тёмный интерфейс в стиле solidtime.

Пользователь — один человек на своём компьютере. Сценарий дня: приложение
висит в трее; задача стартует из главного окна; поверх рабочих окон висит
полупрозрачный мини-таймер с паузой/стопом; потом — отчёт по задачам и дням.

## 2. Цели

1. Первая версия — **ядро** (§5). Остальные функции solidtime — позже, по
   необходимости (§6).
2. Нативное окно Windows, сворачивание в трей, плавающий мини-таймер.
3. Интерфейс визуально как у solidtime (тёмная тема, боковое меню, строка
   таймера сверху, карточки/таблицы, графики).
4. Многоязычность: en (базовый и fallback), ru, zh-CN, es; новые языки
   добавляются сообществом без правки кода.
5. Механизм автообновления реализован, но **выключен** (§9.3).
6. Лёгкость: ориентир **≤ 50 МБ RAM в простое** (главное окно в трее,
   мини-таймер показан), CPU ≈ 0 % в простое, холодный старт ≤ 1 с,
   установщик ≤ 20 МБ.

## 3. Не-цели

- Аккаунты, вход/регистрация, 2FA, профиль, организации/команды, участники,
  роли, приглашения, API/OAuth-токены, e-mail-напоминания, платные функции
  («Upgrade»-бейджи), публичные ссылки на отчёты.
- Синхронизация между устройствами, облако, многопользовательский режим.
- **Учёт перерывов**: пауза не создаёт записей, тип записи «перерыв» из
  solidtime не переносится.
- **Определение бездействия (idle detection).**
- **Импорт** из других трекеров (в первой версии).
- macOS/Linux-сборки (код не должен им мешать, но не тестируется и не
  пакуется).

## 4. Анти-цели (провал, даже если «работает»)

- Приложение заметно ест память/CPU в фоне (постоянная перерисовка, RAM
  сильно выше ориентира). *(Решение исполнителя.)* Память меряем как
  private working set (колонка «Память» в Диспетчере задач); 50 МБ —
  ориентир, а не жёсткий порог приёмки. Если не укладываемся — главное окно
  при уходе в трей уничтожается, а не скрывается; рендерер Slint выбирается
  по замеру.
- Потеря времени: краш, перезагрузка Windows или сон не должны терять
  идущий таймер или паузу.
- Невозможно понять, сколько времени ушло на задачу **в конкретный день**.
- Интерфейс выглядит «программистским»/утилитарным, а не как solidtime.
- Строки интерфейса зашиты в код (ломает перевод сообществом).
- В репозитории появляется код/строки/переводы solidtime (AGPL) — см. §11.

## 5. Функциональность первой версии (ядро)

Источник истины по поведению — solidtime (`resources/js`, `app/`), но
реализуем своё.

### 5.1 Таймер и записи (экран «Время»)
- Строка таймера сверху (на всех экранах): описание, выбор
  «проект › задача» (комбобокс с поиском, создание проекта/задачи на лету),
  теги (мультивыбор, создание на лету), флаг «оплачиваемое», время сессии,
  кнопки **Старт / Пауза·Продолжить / Стоп**.
- Список записей по дням с суммой за день; у записи — ▶ «продолжить»
  (новая сессия с теми же атрибутами), правка (диалог: описание, проект,
  задача, теги, billable, начало/конец), удаление, дублирование.
- Ручное добавление записи (начало/конец или длительность).
- Опция «запрещать пересекающиеся записи» (в настройках, по умолчанию
  выкл.), как в solidtime.

### 5.2 Пауза и сессии (решено с пользователем)
- **Сессия** — непрерывная работа над одной задачей с возможными паузами;
  состоит из записей.
- **Пауза** закрывает текущую запись (`end = now`). Время паузы **нигде не
  записывается** — это просто промежуток между записями.
- **Продолжить** создаёт новую запись в той же сессии с теми же описанием/
  проектом/задачей/тегами/billable.
- **Стоп** закрывает запись (если идёт) и завершает сессию.
- **Пауза может висеть сколько угодно, в том числе через ночь.**
- Строка таймера и мини-таймер показывают **время сессии** (сумма её
  записей + текущая). *(Решение исполнителя.)* Мини-таймер ниже мелко
  показывает «сегодня: Xч Yм» по этой задаче, если сессия началась не
  сегодня.
- **Учёт по дням** *(решение исполнителя)*: запись никогда не пересекает
  локальную полночь. Идущая запись в полночь автоматически закрывается
  ровно в 00:00 (интервалы полуоткрытые `[start, end)`) и продолжается
  новой записью той же сессии с 00:00
  (при сне/выключенном приложении — при ближайшем запуске/пробуждении
  нарезается задним числом). Ручная запись через полночь при сохранении
  делится так же. Благодаря этому списки, отчёты и экспорт всегда точно
  показывают время по каждому дню без особых правил.
- Состояние сессии хранится в БД, переживает перезапуск, краш и сон;
  выход из приложения сессию не завершает.
- *(Решение исполнителя.)* Правка описания/проекта/задачи/тегов/billable
  в строке таймера во время сессии меняет текущую запись и последующие
  записи сессии; уже закрытые записи не трогаются.
- *(Решение исполнителя.)* Старт другой задачи (из списка, со страницы
  проекта, ▶ у записи, из обзора) во время идущей или поставленной на паузу
  сессии завершает текущую (как Стоп) и начинает новую.

### 5.3 Обзор (Dashboard)
- Карточки как в solidtime: недавно отслеживаемые задачи (быстрый старт),
  последние 7 дней, график активности (heatmap), текущая неделя
  (столбцы по дням + таблица по проектам), диаграмма по проектам.

### 5.4 Проекты, задачи, клиенты, теги
- **Проект:** имя, цвет, клиент, оплачиваемость по умолчанию, ставка,
  оценка времени + прогресс (потрачено/оценка), архивирование.
- **Страница проекта:** задачи (создание, правка, «выполнено», оценка,
  ▶ старт по задаче), потраченное время.
- **Клиент:** имя, архивирование. **Тег:** имя.
- Поиск, сортировка, показ архивных, удаление (с подтверждением; при
  наличии записей — запрет или предложение архивировать).

### 5.5 Оплачиваемость
- Эффективная ставка оплачиваемой записи = ставка проекта, если задана,
  иначе ставка по умолчанию (как в solidtime ставка вычисляется, а не
  вводится в записи). Неоплачиваемая запись — 0. Валюта (ISO-код) и её
  формат — в настройках. Деньги — в минорных единицах (центах).
- Флаг billable новой записи по умолчанию берётся из проекта.

### 5.6 Сводный отчёт
- Фильтры: период (пресеты: сегодня, вчера, эта/прошлая неделя, этот/
  прошлый месяц, этот год, свой диапазон), проекты, задачи, клиенты, теги
  (режим «любой/все»), billable.
- Группировка в два уровня: проект / задача / клиент / тег / billable /
  описание / **день**. Интервал графика: день/неделя/месяц.
- Столбчатая диаграмма по интервалу + круговая по первой группировке,
  таблица (длительность, сумма).
- Округление: вверх/вниз/до ближайшего, шаг в минутах — для каждой записи
  отдельно, как в solidtime: начало усекается до минуты, длительность
  округляется до шага.
- Экспорт в **CSV и XLSX** (таблица отчёта и список записей за период).

### 5.7 Настройки
- Язык; формат даты (6 вариантов solidtime), времени (12/24 ч), интервалов
  (decimal, «ч мин», `h:mm`, `h:mm:ss`), чисел (5 вариантов), валюты
  (6 вариантов); первый день недели; часовой пояс (по умолчанию системный);
  тема (тёмная по умолчанию, светлая).
- Мини-таймер: показывать/нет, прозрачность в покое (по умолчанию 70 %
  прозрачности = 30 % видимости), положение запоминается.
- Поведение: ✕ сворачивает в трей; автозапуск с Windows (вкл/выкл).
- Данные: резервная копия базы в файл и восстановление из файла.
- Обновления: секция скрыта, пока не задан источник (§9.3).
- «О программе»: версия, атрибуция Slint (обязательна, §11).

## 7. Окна и трей

### 7.1 Главное окно
Нативное окно с системной рамкой. Боковое меню первой версии: Обзор, Время
│ Проекты, Клиенты, Теги │ Отчёты │ Настройки. Сверху — строка таймера.
Макет согласован (`.superpowers/brainstorm/*/content/layout.html`; пункты
из §6 в нём показаны, но в v1 не входят).

### 7.2 Мини-таймер
- Отдельное окно без рамки, всегда поверх, без кнопки на панели задач,
  перетаскивается за ручку, скруглённые углы, прозрачный фон.
- Содержимое: цветная точка + «проект › задача», описание, время сессии,
  кнопки Пауза/Продолжить и Стоп; клик по тексту открывает главное окно.
  Нет сессии — «Нет активной задачи» + кнопка старта последней задачи.
- **Без наведения мыши** — непрозрачность 30 % (настраивается),
  **при наведении** — 100 %, плавный переход.
- Показ/скрытие — из трея, главного окна, настроек.

### 7.3 Трей
- Иконка различается: идёт / пауза / остановлено; тултип — задача и время.
- Меню: задача и время (неактивный пункт) │ Пауза/Продолжить, Стоп │
  Показать/скрыть мини-таймер │ Открыть окно, Выход.
- Левый клик — открыть/скрыть главное окно. Выход — только из меню.
- Одна копия приложения: повторный запуск активирует запущенную.

## 8. Локализация

- Механизм Slint `@tr()` (gettext): `.po` на язык в `translations/`,
  множественные формы (критично для ru). Строки из Rust (трей, ошибки,
  экспорт) — через тот же каталог.
- en (исходный, fallback), ru, zh-CN, es. Первый запуск — язык Windows,
  если поддержан, иначе en. Смена в настройках — без перезапуска.
- Даты/числа/валюта — по настройкам формата (§5.7).
- Шрифты: Inter (встроен) для латиницы/кириллицы, CJK — системные
  (Microsoft YaHei UI) через fallback; ввод через IME должен работать.
- `docs/translating.md`: как добавить язык (из `.pot`, Poedit/Weblate, PR).

## 9. Архитектура и стек

**Rust (stable), один cargo workspace.** Зависимости только вниз:

| Крейт | Ответственность |
|---|---|
| `tt-domain` | Сущности и правила: сессии/пауза, нарезка по полночи, ставки, округление, агрегации отчёта, форматирование. Без I/O. |
| `tt-storage` | SQLite (`rusqlite`, bundled), миграции по `user_version`, репозитории. |
| `tt-services` | Сценарии: таймер, CRUD, отчёты, экспорт CSV/XLSX (`rust_xlsxwriter`), бэкап, обновления. Domain + storage через трейты. |
| `tt-app` | Бинарник: UI на **Slint**, трей (`tray-icon`), мини-окно, single-instance, автозапуск. |

### 9.1 UI
- **Slint** (пользователь решил: нативный GUI без веб-движка; выбор именно
  Slint — решение исполнителя, §13). Свои токены темы (цвета, отступы,
  радиусы, типографика) по мотивам Tailwind-темы solidtime.
- Делаем сами: комбобокс с поиском и созданием, мультивыбор тегов, выбор
  даты/диапазона, поле длительности, диаграммы (столбцы, круг, heatmap —
  примитивами Slint), тосты, модальные диалоги, виртуализированный список.
- Без постоянной перерисовки: тик раз в секунду меняет только текст
  времени; скрытое окно не рендерится.

### 9.2 Данные
- Время — UTC в БД, отображение в часовом поясе из настроек. Идущая запись
  = `end IS NULL` (защита от потери при краше).
- `%APPDATA%\TimeTracker\timetracker.db`, WAL. Логи —
  `%LOCALAPPDATA%\TimeTracker\logs`, без описаний задач и прочего
  пользовательского текста.
- Модель (по мотивам solidtime, без org/member/user):
  - `clients(id, name, archived_at, created_at, updated_at)`
  - `projects(id, name, color, client_id?, is_billable, billable_rate?, estimated_time?, archived_at, …)`
  - `tasks(id, project_id, name, estimated_time?, done_at?, …)`
  - `tags(id, name, …)`
  - `timer_sessions(id, started_at, ended_at?, state)` — state: running/paused/stopped
  - `time_entries(id, session_id?, description, start, end?, billable, project_id?, task_id?, …)` (клиент — через проект)
  - `time_entry_tags(time_entry_id, tag_id)`
  - `settings(key, value)`
  - ID — UUID v7. `spent_time` считаем запросом, не храним.

### 9.3 Обновления (реализовано, выключено)
- Проверка JSON-манифеста (версия, URL установщика, ed25519-подпись) по
  URL, задаваемому при сборке; установщик проверяется подписью перед
  запуском.
- В текущих сборках URL не задан → проверка не выполняется, секция
  настроек скрыта. Включение — задать URL и публичный ключ в конфиге сборки.
- Сертификата Authenticode пока нет: SmartScreen будет предупреждать при
  установке — известное ограничение.

### 9.4 Сборка и поставка
- Установщик per-user без прав администратора (MSI через `cargo-wix` или
  NSIS через `cargo-packager` — на выбор исполнителя).

## 12. Решено пользователем

- Windows-десктоп, трей, мини-таймер поверх окон: прозрачный на 70 % без
  наведения, полностью видим при наведении.
- Таймер привязан к задаче, есть пауза; пауза не создаёт записей перерыва,
  может висеть через ночь; время по задаче должно быть видно по каждому дню.
- Старт задач из окна приложения.
- Функциональность solidtime без аккаунтов; в первой версии — ядро,
  остальное по необходимости; импорта пока нет.
- Интерфейс как у solidtime; языки en (база), ru, zh-CN, es.
- Нативный GUI без веб-движка, Rust; память — приоритет.
- Закрытая разработка, лицензия позже.
- Автообновление реализовать, но выключить; определения бездействия нет.

## 13. Решения исполнителя (можно оспорить)

  бэкап базы в v1, группировка отчёта по дню.
- Нарезка записей по полночи; поведение при правке/смене задачи во время
