# TimeTracker 0.3.0 для macOS — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить 0.3.0 с одним универсальным `.dmg` (Apple Silicon + Intel), в котором TimeTracker работает на macOS так же, как на Windows и Linux: значок в строке меню, «закрыть в строку меню», мини-таймер поверх окон, автозапуск при входе, один экземпляр. Windows- и Linux-сборки не меняются.

**Architecture:** Новый платформенный код лежит в `crates/tt-app/src/platform/`, macOS-ветки стоят под `#[cfg(target_os = "macos")]`. Чистая логика (разбор plist LaunchAgent, выбор пути сокета, проверка места установки, реакция на клик по значку) компилируется на всех системах и тестируется на Windows. Вызовы AppKit (политика Dock, делегат «повторного открытия») — тонкие функции на `objc2-app-kit`: эти крейты уже есть в `Cargo.lock` через winit и Slint. `.app` собирается скриптом из двух бинарников (`lipo`), подписывается ad-hoc и упаковывается в `.dmg` через `hdiutil` на раннере `macos-14`.

**Tech Stack:** Rust 1.95, Slint 1.18.1 (winit 0.30, software renderer), `tray-icon` 0.26, `auto-launch` 0.6 (`MacOSLaunchMode::LaunchAgent`), `objc2` 0.6 / `objc2-app-kit` 0.3, `lipo`, `codesign`, `hdiutil`, `plutil`, GitHub Actions `macos-14`.

**Spec:** `docs/superpowers/specs/2026-11-11-cross-platform-design.md` (§5.1, §5.3, §6). Исполнитель читает спеку вместе с этим планом.

## Global Constraints

- Windows и Linux: поведение, установщики, автозапуск, single-instance, файлы релиза и их имена не меняются (анти-цель спеки §4). Изменённый общий код проверяется тестами на Windows и CI на Linux.
- Платформенный код только в `crates/tt-app/src/platform/`. Вне этой папки `cfg(target_os)` допустим лишь в `main.rs`.
- Rust 1.95, Slint 1.18.1, только software renderer. Новые прямые зависимости — только `objc2` и `objc2-app-kit` для `cfg(target_os = "macos")`, тех версий, что уже в `Cargo.lock` (0.6.x и 0.3.x). `cargo deny check licenses advisories` проходит для всех целей из `deny.toml`.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` проходят на Windows, Linux и macOS (CI).
- `unsafe_code = "deny"` в workspace остаётся. Где без `unsafe` никак (делегат приложения), — `#[allow(unsafe_code)]` на минимальном элементе и комментарий `// SAFETY:`.
- Пользовательские строки — через `@tr()`; новая строка попадает в `translations/tt-app.pot` и во все `.po` (`ru`, `zh_CN`, `es`). Тест `cargo test -p tt-app --test translations`.
- Без кода и строк solidtime.
- Пути данных не меняются: `directories::BaseDirs`, на macOS `~/Library/Application Support/TimeTracker/` (база и `logs/`).
- Проверка обновлений на macOS выключена: CI-сборка macOS не получает `TT_UPDATE_URL` / `TT_UPDATE_PUBKEY`.
- Без нотаризации и без сертификата Apple: только ad-hoc подпись (`codesign -s -`).
- Минимальная macOS — 11.0 (`MACOSX_DEPLOYMENT_TARGET=11.0`, `LSMinimumSystemVersion`). Решение автора плана: 11.0 — первая версия с Apple Silicon, так один порог на обе архитектуры.
- Bundle id `io.github.olegfm.timetracker`, исполняемый файл в бандле `TimeTracker`. Решение автора плана.
- Коммит после каждой задачи. Push, теги и релизы — только с явного разрешения пользователя.

## Перед началом: как проверяется macOS-код

На машине автора Windows, а Mac нет. macOS-код нельзя скомпилировать локально: `rusqlite` с `bundled` собирает C-код, и для этого нужен Apple SDK. Поэтому так:

- Чистая логика компилируется на всех системах, и её тесты идут на Windows (`cargo test --workspace`).
- Всё под `cfg(target_os = "macos")` проверяет только CI: job `check` на `macos-14` появляется в задаче 1. Контроллер пушит ветку `feature/macos-0.3.0` после каждой задачи с macOS-кодом (1, 2, 3, 4, 7) и ждёт зелёный `check (macos-14)`, прежде чем закрыть задачу. **Первый push спросить у пользователя** и получить разрешение на push этой ветки на весь план.
- Поведение на живом Mac (Dock, строка меню, повторное открытие, автозапуск) проверяет тестировщик по QA-чеклисту из задачи 8, на сборке из предрелиза `v0.3.0-rc.N`. Тег на ветке ставит пользователь.

Работа идёт в отдельной ветке `feature/macos-0.3.0` от `main` (worktree по `superpowers:using-git-worktrees`, например `E:\Work\TimeTracker-macos`). Ветка `feature/linux-0.2.0` может ещё получать правки по Linux-предрелизу. Эти правки не трогают macOS-файлы. Конфликты в CHANGELOG и чеклисте решаются при слиянии.

## Review Focus

1. **Программу запустили прямо из `.dmg` или из «Загрузок», и включили автозапуск.** macOS запускает такую программу из временной копии (App Translocation, `/private/var/folders/.../AppTranslocation/...`) или с тома `/Volumes/...`. Этот путь исчезает, и запись автозапуска на него сломается. Ожидание: запись не пишется, в лог идёт предупреждение. README велит сначала перенести программу в «Программы». Тест `permanent_location_*` в задаче 3.
2. **Plist LaunchAgent читается обратно.** Запись, которую пишет `auto-launch`, при следующем запуске должна дать `SyncPlan::Keep`, а не перезапись на каждом старте. Это касается и пути с пробелами. Тест `launch_agent_round_trip_*` в задаче 3.
3. **launchd и Finder дают процессу разный `TMPDIR`.** Иначе автозапуск и запуск из Finder поднимут два экземпляра. Ожидание: путь сокета не зависит от `TMPDIR`, а длинный домашний путь (лимит `sun_path` — 104 байта) не ломает запуск. Тесты `socket_path_*` в задаче 2.
4. **Повторный запуск из Finder, Launchpad или Spotlight, когда окно спрятано в строку меню.** macOS не стартует второй процесс, а «переоткрывает» первый. Ожидание: главное окно показывается. Это проверяют только руками: QA-пункт в задаче 8. Делегат — в задаче 4.
5. **Левый клик по значку в строке меню.** На macOS левый клик открывает меню. Окно при этом не должно прятаться или показываться: на Windows то же нажатие переключает окно. Тест `click_on_macos_*` в задаче 4.

### Task 2: Один экземпляр на macOS — путь сокета

**Files:**
- Modify: `crates/tt-app/src/platform/single_instance/mod.rs`
- Modify: `crates/tt-app/src/platform/single_instance/unix.rs` (`acquire`)

**Interfaces:**
- Consumes: `socket_path(runtime_dir: Option<PathBuf>, temp_dir: PathBuf, user: Option<String>) -> PathBuf` (уже есть).
- Produces: `socket_path` с той же сигнатурой, но с проверкой длины. На macOS `acquire()` передаёт `runtime_dir = Some(<BaseDirs::data_dir()>/TimeTracker)` и до этого создаёт эту папку (`create_dir_all`). На Linux вызов не меняется.

### Task 3: Автозапуск на macOS (LaunchAgent)

**Files:**
- Create: `crates/tt-app/src/platform/autostart/launch_agent.rs`
- Modify: `crates/tt-app/src/platform/autostart/mod.rs`

**Interfaces:**
- Consumes: `StoredEntry`, `plan_sync`, `quoted`, `MINIMIZED_ARG` из `autostart/mod.rs`.
- Produces (в `launch_agent.rs`, компилируется везде, `#![cfg_attr(not(target_os = "macos"), allow(dead_code))]`, как `xdg.rs`):
  - `pub fn parse_launch_agent(text: &str) -> StoredEntry`: читает `ProgramArguments`, `command = Some("\"<arg0>\" <arg1> <arg2>...")` в том же формате, что `expected` в `sync`; `disabled` всегда `false` (переключатель «Разрешить в фоне» macOS хранит не в файле).
  - `pub fn permanent_location(exe: &Path) -> bool`: `false`, если путь начинается с `/Volumes/` или содержит компонент `AppTranslocation`.
  - `#[cfg(target_os = "macos")] pub fn stored_entry() -> StoredEntry`: читает `~/Library/LaunchAgents/TimeTracker.plist` (путь от `BaseDirs::home_dir()`, как у крейта), нет файла — `StoredEntry::default()`.

Как `auto-launch` 0.6 пишет файл (`build_launch_agent_plist` в его `src/macos.rs`): `<key>ProgramArguments</key>\n  <array><string>{app_path}</string><string>{arg}</string>…</array>` без XML-экранирования. Крейт кладёт `app_path` в `<string>` как есть и в `enable()` проверяет `Path::new(app_path).exists()`. Поэтому **на macOS путь передаётся без кавычек**, а `quoted()` остаётся только для строки сравнения `expected`.

### Task 4: Строка меню и Dock

**Files:**
- Create: `crates/tt-app/src/platform/dock.rs`
- Modify: `crates/tt-app/src/platform/mod.rs` (`pub mod dock;`)
- Modify: `crates/tt-app/src/platform/tray.rs` (левый клик на macOS)
- Modify: `crates/tt-app/src/platform/window_ext.rs` (`show_and_focus`)
- Modify: `crates/tt-app/src/controllers/tray.rs` (`AppAction::ToggleMain`)
- Modify: `crates/tt-app/src/main.rs`
- Modify: `crates/tt-app/Cargo.toml`

**Interfaces:**
- Produces (`platform/dock.rs`):
  - `pub fn set_visible(on: bool)`: на macOS — `NSApplication::sharedApplication(mtm).setActivationPolicy(Regular | Accessory)`, где `mtm = MainThreadMarker::new()`; если `None`, — `log::warn!` и выход. На других системах ничего не делает.
  - `pub fn on_reopen(f: impl Fn() + 'static)`: на macOS ставит `NSApplicationDelegate` с методом `applicationShouldHandleReopen:hasVisibleWindows:`, который вызывает `f` и возвращает `true`. Делегат держится в `thread_local!` (NSApplication хранит делегата слабой ссылкой). На других системах ничего не делает. Вызывать после `MainWindow::new()`: winit создаёт NSApplication в `EventLoop::new` и сам делегата не ставит (см. `winit/src/platform/macos.rs`, раздел «Custom NSApplicationDelegate»).
- Produces (`platform/tray.rs`): `const MENU_ON_LEFT_CLICK: bool = cfg!(target_os = "macos");` и `fn click_action(e: &TrayIconEvent, menu_on_left_click: bool) -> Option<AppAction>`, который возвращает `None` при `menu_on_left_click`. `TrayIconBuilder::with_menu_on_left_click(MENU_ON_LEFT_CLICK)`; обработчик вызывает `click_action(&e, MENU_ON_LEFT_CLICK)`.

Поведение (спека §5.3): значок Dock виден, только пока показано главное окно. Мини-таймер его не показывает и не попадает в `Cmd+Tab`.

```rust
struct Ivars { on_reopen: Box<dyn Fn()> }

define_class!(
    #[unsafe(super(NSObject))]
    #[thread_kind = MainThreadOnly]
    #[name = "TimeTrackerAppDelegate"]
    #[ivars = Ivars]
    struct AppDelegate;

    unsafe impl NSObjectProtocol for AppDelegate {}

    unsafe impl NSApplicationDelegate for AppDelegate {
        #[unsafe(method(applicationShouldHandleReopen:hasVisibleWindows:))]
        fn should_handle_reopen(&self, _app: &NSApplication, _visible: bool) -> bool {
            (self.ivars().on_reopen)();
            true
        }
    }
);
```

Формат ICNS: `b"icns"` + длина файла (u32 big-endian), затем записи «тип (4 байта) + длина записи с заголовком (u32 BE) + PNG». Записи и размеры PNG: `icp4` 16, `icp5` 32, `ic11` 32, `ic12` 64, `ic07` 128, `ic13` 256, `ic08` 256, `ic14` 512, `ic09` 512, `ic10` 1024. Рисунок тот же (градиентный квадрат с часами), но по сетке значков macOS. Скруглённый квадрат занимает 824/1024 холста и стоит по центру, поля прозрачные. Иначе значок в Dock будет крупнее соседних. Решение автора плана.

- [ ] **Step 1: Write the failing test** (`tests/icns.rs`)

```rust
#[test]
fn icns_has_a_valid_header_and_the_1024_png() {
    let data = std::fs::read(concat!(env!("CARGO_MANIFEST_DIR"), "/assets/app.icns")).unwrap();
    assert_eq!(&data[..4], b"icns");
    assert_eq!(u32::from_be_bytes(data[4..8].try_into().unwrap()) as usize, data.len());
    let mut types = Vec::new();
    let mut i = 8;
    while i < data.len() {
        let len = u32::from_be_bytes(data[i + 4..i + 8].try_into().unwrap()) as usize;

        types.push(String::from_utf8(data[i..i + 4].to_vec()).unwrap());
        i += len;
    }
    assert_eq!(i, data.len());
    for t in ["icp4", "icp5", "ic11", "ic12", "ic07", "ic13", "ic08", "ic14", "ic09", "ic10"] {
        assert!(types.iter().any(|x| x == t), "{t}");
```
