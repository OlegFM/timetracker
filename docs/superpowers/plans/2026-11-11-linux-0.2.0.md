# TimeTracker 0.2.0 для Linux — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить 0.2.0, в котором TimeTracker работает на Ubuntu 22.04/24.04 (AppImage и `.deb`, x86_64) так же, как на Windows, а Windows-сборка не меняется.

**Отступление от спеки (в лучшую сторону):** спека §5.2 считала, что левый клик по значку на Linux открывает меню. С бэкендом `ksni` (`MENU_ON_ACTIVATE = false`) левый клик приходит как `Click`, поэтому окно показывается и прячется, как на Windows, а меню открывается правым кликом. QA-чеклист проверяет именно это.

**Architecture:** Весь платформенный код остаётся в `crates/tt-app/src/platform/`. Чистая логика (разбор `.desktop`, выбор путей, решения при запуске) компилируется на всех системах и тестируется на Windows. Вызовы ОС стоят за `#[cfg(windows)]` / `#[cfg(unix)]` / `#[cfg(target_os = "linux")]`. Трей на Linux работает через бэкенд `ksni` крейта `tray-icon`: это чистый D-Bus без GTK. XWayland включается тем, что Slint собирается только с X11-бэкендом winit.

**Tech Stack:** Rust 1.95, Slint 1.18.1 (`backend-winit-x11`, software renderer), `tray-icon` 0.26 (feature `ksni`), `zbus` 5 (уже есть в `Cargo.lock` через `accesskit_unix`), `auto-launch` 0.6, `rfd` 0.18, `std::os::unix::net`, `cargo-deb`, `appimagetool`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-cross-platform-design.md`. Исполнитель читает спеку вместе с этим планом.

## Global Constraints

- Windows: поведение, установщик, автозапуск, single-instance, файлы релиза и их имена не меняются (анти-цель спеки §4).
- Платформенный код только в `crates/tt-app/src/platform/`. Вне этой папки `cfg(target_os)` допустим лишь в `main.rs`.
- Rust 1.95, Slint 1.18.1, только software renderer. Новые крейты в `Cargo.lock` — только `ksni` и его зависимости (через feature `tray-icon`), прямой `zbus` — той же версии, что уже в lock. `cargo deny check licenses advisories` проходит.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` проходят на Windows и на Linux.
- Пользовательские строки — через `@tr()`; новая строка попадает в `translations/tt-app.pot` и во все `.po` (`ru`, `zh_CN`, `es`). Тест `cargo test -p tt-app --test translations`.
- Без кода и строк solidtime.
- Пути данных не меняются: `directories::BaseDirs`, на Linux `~/.local/share/TimeTracker/`.
- Проверка обновлений на Linux не компилируется (спека §3).
- Цель Linux: Ubuntu 22.04 и 24.04 с GNOME, x86_64. Сборка в CI на `ubuntu-22.04`.
- macOS в этом плане не делается. Linux-ветки пишутся под `cfg(unix)` там, где код подойдёт и для macOS (single-instance), и под `cfg(target_os = "linux")` там, где он только для Linux. macOS-строка CI появится в 0.3.0.
- Коммит после каждой задачи; push, теги и релизы делает пользователь или делается с его явного разрешения.

## Review Focus

1. **Вход в систему: программа стартует раньше, чем GNOME поднимет трей.** Автозапуск с `--minimized` не должен «решить, что трея нет»: ждём хост трея до 10 с. Тест `wait_until_*` в задаче 4.
2. **AppImage в автозапуске.** `Exec=` должен указывать на сам файл `.AppImage` (`$APPIMAGE`), а не на временную точку монтирования `/tmp/.mount_*`. Тест `launch_target_*` в задаче 1.
3. **Сокет остался после падения.** Следующий запуск не должен считать, что программа уже работает. Тест `stale_socket_is_replaced` в задаче 2.
4. **Автозапуск выключен в GNOME Tweaks / «Автозапуск приложений»** (`X-GNOME-Autostart-enabled=false` или `Hidden=true`). Настройка выключается, файл не трогается. Тесты `desktop_entry_*` и `plan_sync` в задаче 1.
5. **Версия предрелиза в `.deb`.** `0.2.0-rc.1` должна стать `0.2.0~rc.1`, чтобы `0.2.0` ставился поверх. Проверка в CI в задаче 6.

### Задача 2: Один экземпляр на Unix

**Files:**
- Delete: `crates/tt-app/src/platform/single_instance.rs`
- Create: `crates/tt-app/src/platform/single_instance/mod.rs` — `#[cfg(windows)] mod windows; #[cfg(unix)] mod unix;` и реэкспорт `acquire`, `InstanceGuard` из нужного; общая чистая `socket_path` (компилируется везде, `#[cfg_attr(windows, allow(dead_code))]`) и её тест.
- Create: `crates/tt-app/src/platform/single_instance/windows.rs` — нынешний файл без изменений (с его тестом).
- Create: `crates/tt-app/src/platform/single_instance/unix.rs`.

**Interfaces:**
- Produces (такие же, как в Windows-версии; `main.rs` не меняется):
  - `pub fn acquire() -> anyhow::Result<Option<InstanceGuard>>`.
  - `impl InstanceGuard { pub fn on_activate(&mut self, f: impl Fn() + Send + Sync + 'static) }`. Вызывает `f` через `slint::invoke_from_event_loop` на каждый вход второго экземпляра.
  - `pub fn socket_path(runtime_dir: Option<PathBuf>, temp_dir: PathBuf, user: Option<String>) -> PathBuf` (`mod.rs`).
- В `unix.rs`, частное: `fn acquire_at(path: &Path) -> anyhow::Result<Option<InstanceGuard>>` и `fn listen(&mut self, notify: impl Fn() + Send + 'static)`; `on_activate` = `listen` с `invoke_from_event_loop`.

Механизм (решение плана): Unix-сокет `std::os::unix::net`, без новых зависимостей и без `unsafe`. Первый экземпляр делает `bind`. Если `bind` вернул `AddrInUse`, программа пробует `connect`. Удалось → это второй экземпляр: само соединение и есть сигнал, процесс возвращает `None`. Получен `ConnectionRefused` → файл остался после падения: удалить и повторить `bind` один раз. Поток слушателя (`name("instance-activate")`) в цикле `accept` вызывает `notify`, пока не выставлен флаг `stop`. `Drop`: выставить `stop`, подключиться к своему сокету, чтобы разбудить `accept`, сделать `join`, удалить файл.

```rust
#[test]
fn second_acquire_signals_the_first_and_fails() {
    let dir = tempfile::tempdir().unwrap();
    let path = dir.path().join("tt.sock");
    let mut first = acquire_at(&path).unwrap().expect("first instance");
    let (tx, rx) = std::sync::mpsc::channel();
    first.listen(move || tx.send(()).unwrap());
    assert!(acquire_at(&path).unwrap().is_none(), "second instance");
    rx.recv_timeout(std::time::Duration::from_secs(2)).expect("activation");
    drop(first);
    assert!(!path.exists(), "socket removed on exit");
    assert!(acquire_at(&path).unwrap().is_some(), "free after exit");
}

#[test]
fn stale_socket_is_replaced() {
    let dir = tempfile::tempdir().unwrap();
    let path = dir.path().join("tt.sock");
    drop(std::os::unix::net::UnixListener::bind(&path).unwrap()); // file stays, nobody listens
    assert!(path.exists());
    assert!(acquire_at(&path).unwrap().is_some());
}
```

### Задача 4: Трей на Linux и поведение без трея

**Files:**
- Create: `crates/tt-app/src/platform/tray_host.rs` (+ `pub mod tray_host;` в `platform/mod.rs`).
- Modify: `crates/tt-app/Cargo.toml` — `[target.'cfg(target_os = "linux")'.dependencies] zbus = { version = "5", default-features = false, features = ["blocking-api", "async-io"] }`. Версия должна совпадать с той, что уже в lock (5.19). После правки `cargo tree -d -i zbus --target x86_64-unknown-linux-gnu` не показывает второй версии.
- Modify: `crates/tt-app/src/app.rs` — `InitialWindow`, `initial_window`, поле `AppContext::has_tray`.
- Modify: `crates/tt-app/src/controllers/tray.rs` — `install` возвращает `Option<Rc<Tray>>`.
- Modify: `crates/tt-app/src/main.rs` — порядок запуска и закрытие окна.
- Modify: `crates/tt-app/src/controllers/settings.rs`, `crates/tt-app/ui/bridges/settings.slint`, `crates/tt-app/ui/screens/settings.slint`.
- Modify: `translations/tt-app.pot`, `translations/{ru,zh_CN,es}/LC_MESSAGES/tt-app.po`.

**Interfaces:**
- Produces:
  - `tray_host::TRAY_WAIT_AT_LOGIN: Duration = Duration::from_secs(10)`.
  - `tray_host::available(wait: Duration) -> bool`. Windows — всегда `true`. Linux — `wait_until(watcher_present, wait, Duration::from_millis(500))`.
  - `tray_host::wait_until(probe: impl FnMut() -> bool, timeout: Duration, step: Duration) -> bool` (везде): проба сразу, затем каждые `step`, пока не истёк `timeout`; при `timeout == 0` — одна проба.
  - `#[cfg(target_os = "linux")] fn watcher_present() -> bool`: `zbus::blocking::Connection::session()` → `zbus::blocking::fdo::DBusProxy::new(&conn)?.name_has_owner("org.kde.StatusNotifierWatcher")`. Любая ошибка (нет сессионной шины и т. п.) → `false` и `log::warn!`.
  - `app::InitialWindow { Shown, Hidden, Minimized }` и `app::initial_window(minimized: bool, tray: bool) -> InitialWindow`.
